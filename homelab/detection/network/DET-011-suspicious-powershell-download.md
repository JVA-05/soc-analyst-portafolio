# DET-011 — Suspicious PowerShell Download

## Detection Overview

| Field | Value |
|---|---|
| Detection ID | DET-011 |
| Detection Name | Suspicious PowerShell Download |
| Category | Network |
| Status | Enabled |
| Severity | Not confirmed |
| Platform | Splunk Enterprise |
| Data Source | Sysmon |
| Index | `sysmon` |
| Event ID | 1 — Process Creation |
| Monitored Host | `DESKTOP-1BDISO6` |

## Objective

Identify PowerShell processes executing commands or .NET methods commonly associated with downloading files or retrieving remote content.

This detection helps analysts identify potentially suspicious download activity initiated through PowerShell and provides process context for further investigation.

A matching command line is an indicator of possible download activity. It does not independently confirm that a download succeeded or that the retrieved content was malicious.

## Data Sources

The detection uses Sysmon Process Creation events.

Relevant fields:

| Field | Description |
|---|---|
| `_time` | Process creation timestamp |
| `host` | Monitored endpoint |
| `User` | Account that executed the process |
| `Image` | PowerShell executable path |
| `ParentImage` | Parent process executable |
| `ProcessId` | Process identifier |
| `ParentProcessId` | Parent process identifier |
| `ProcessGuid` | Unique process identifier |
| `ParentProcessGuid` | Unique parent process identifier |
| `CommandLine` | Full process command line |

## Detection Logic

The detection searches for Sysmon Event ID 1 events generated by PowerShell processes.

It identifies command-line references to:

- `Invoke-WebRequest`
- `Invoke-RestMethod`
- `Start-BitsTransfer`
- `DownloadFile`
- `DownloadString`
- `DownloadData`
- `System.Net.WebClient`
- `iwr` and `irm` aliases

The executable filter includes both `powershell.exe` and `pwsh.exe`.

The results include process and parent-process identifiers to support correlation with other Sysmon events.

## SPL Query

```spl
index=sysmon host="DESKTOP-1BDISO6" EventCode=1
| where match(Image, "(?i)\\\\(powershell|pwsh)\\.exe$")
| where match(CommandLine, "(?i)\\b(Invoke-WebRequest|DownloadFile|DownloadString|Start-BitsTransfer|Invoke-RestMethod|DownloadData|iwr|irm)\\b|System\\.Net\\.WebClient")
| table _time host User Image ParentImage ProcessId ParentProcessId ProcessGuid ParentProcessGuid CommandLine
| sort - _time
```

## Investigation Guidance

When this detection fires, the analyst should:

1. Review the complete PowerShell command line and identify the download method.
2. Identify the user and parent process that initiated the activity.
3. Determine whether the command references a remote URL, IP address, or external resource.
4. Correlate the process with Sysmon Event ID 3 to investigate associated network connections.
5. Correlate with Sysmon Event ID 11 to identify files created on the endpoint.
6. If a downloaded file is identified, calculate its hash and review available reputation or analysis results.
7. Determine whether the activity was authorized and expected before escalating.

## False Positives and Limitations

- Administrators and legitimate applications may use PowerShell to download software, scripts, and updates.
- The presence of a download-related method does not establish malicious intent.
- A matching command line does not prove that a network connection or file transfer succeeded.
- Obfuscated commands and alternative download techniques may evade the detection.
- The detection does not inspect downloaded file contents.
- Sysmon Event ID 1 provides process creation information, not the HTTP response, downloaded content, or transfer result.
- Aliases and command-line variations not included in the matching patterns may not be detected.

## Analyst Notes

This detection is intended to identify potentially suspicious PowerShell download activity, not to classify every matching event as malicious.

The recommended SPL improves coverage of PowerShell executable names and common download methods while preserving process correlation fields.

Any replacement of the existing SPL should be followed by validation of the revised query and alert behavior.
